# Private-Lite isolated prototype — default CLOSED

No Lighthouse deployment, production migration/LOGIN, cloud purchase or public Probe is authorized by this prototype. `private-approved`/fixture entries reject Lite profiles. A separate build of the existing commands (`-ldflags '-X main.executionProfile=private-lite'`) produces `liteprobe`, `litenetwork`, and `liteapproval`; no environment variable can change an existing binary's profile.

The explicit foreground entry is `python3 -S runtime/private_lite/launcher.py run --enable-private-lite --config /absolute/private.json --state /absolute/private-state`. Omitting the flag returns closed without loading configuration or starting Docker. Configuration requires `mode: private-lite`, `enabled: true`, all existing service fields and `lite: {resolver, host_container, host_interface, uplink_interface, source}`. No defaults are provided. The adapter manages a network-none host-stand-in container, never the real host namespace. The supplied acceptance harness wires only owned disconnected receivers.

An operator pins an actual controlled ordinary IPv4 TCP53 endpoint, reviews the entire DNS response with `liteapproval` (request includes `resolver`), and creates the existing scoped/versioned approval/catalog. No system resolver/fallback or 192.0.2.53 is used in Lite. Only a selected IPv4 TCP443 target is admitted; A/AAAA/CNAME validation still runs and dangerous AAAA rejects the complete answer. The infrastructure DNS exception never permits HTTPS.

Runtime status is `private-lite`; the unchanged Worker/SQL protocol remains `private-approved` inside disposable PG18 only. This is explicit protocol reuse, not a database Gate bypass. Owner consent, existing isolated least-privilege SQL identities, existing resource limits, storage admission, original PID1 Supervisor, Permit and signed physical receipts remain required. No new schema or result store is introduced. This disconnected prototype uses the existing disposable test-role naming; it does not claim acceptance of the five production LOGIN/DSN bindings. Those remain a separate deployment requirement.

## Host trust and least privilege

Probe: UID/GID65534, capabilities0, no_new_privs/seccomp, read-only root, only read-only CA/profile plus original anonymous pipes, memory128MiB/CPU1/PID128/FD256. Worker retains only its existing DB credential and internal control network. Neither has NET_ADMIN, Docker socket or host-filter handles. Trusted namespace managers get only NET_ADMIN in their own namespaces; the Lite host-policy helper is started once with native Linux nsenter (root or sudo), validates its exact Docker-bound namespace inode, then drops SYS_ADMIN and every capability except NET_ADMIN. Its anonymous pipes are never passed to Worker/Probe. It has 64MiB address-space/32 FD bounds, a two-second command limit and at most one 64MiB child; PID1 retains only the original termination capabilities. The trusted outer orchestrator retains Docker/signing authority. Host nft/tc/iproute2 commands must be installed on the independent Linux test host; no package/privilege change is applied to Lighthouse by this prototype. All host filter mutations are scoped to fresh veths and uniquely named tables, never `flush ruleset` on the host or edits to existing Docker chains.

Each packet requires positive marks from TC ingress through two host nft tables and TC egress. Both interfaces must be fresh veths, never the management NIC. TC default-drop anchors precede every allow rule and actor. Loss of either nft table, both tables, the entire nft ruleset, or TC ingress rejects traffic. ARP alone is infrastructure-exempt; IPv6 has no egress allow. Timed DNS/target tuples are installed only after namespace preparation / original Permit commit. Runtime shutdown permanently closes host admission under a lock before original physical drain; delayed Permit callbacks cannot reopen it. Approval deletion/change/expiry is checked on every event-loop iteration and before execution commands (normally within 100ms, plus filesystem/host command latency). A stopped or stalled launcher cannot renew the independent timed grants. The helper retains the network namespace directly, so Docker API outage cannot prevent host revocation; parent-pipe EOF also revokes and drops traffic. Neither helper exit nor Docker container stop is a physical release proof. Revocation flushes both tables' grants before original physical drain. There is no unconditional established-flow allowance. Tables remain as deny anchors throughout drain and for every unverified physical domain. Only after the original signed stop protocol has removed all run/gateway namespaces may the trusted runtime atomically retire its own two anchors, allowing a clean restart. This does not release any SQL slot or create a receipt. Deliberate simultaneous removal of all enforcement, hostile root, kernel or daemon compromise is outside this trusted-host model. Namespaces are not VM isolation. Docker 26.1.3 forwarding/published-port NAT and normal/live-restore restart are exercised in a separate network-none daemon; it is never the existing daemon. Lighthouse kernel/routing adoption and capacity remain unproven. Root removal of every independent nft AND TC mechanism remains outside this trusted-host model.

## Targeted acceptance

`sh tests/private_lite/run.sh /absolute/new-evidence-directory` on an independent Linux test host. All data-plane namespaces are network-none, with no default/upstream route; simulated public-shaped DNS/HTTPS addresses are owned only by the isolated receiver. No real target is contacted. Evidence separates packet tests, Go profile checks and existing Owner/PG18/Supervisor/physical-release lifecycle. Existing mode compatibility tests remain intact.

The existing seven control-child memory ceilings sum to 1.75GiB; two concurrent run/gateway/PID1 groups add 0.75GiB, holder/host add 0.25GiB and the native helper plus its single child add at most 0.125GiB address space. These are ceilings, not reservations: the group still has no aggregate host reservation. The read-only Lighthouse snapshot had about 1.40GiB MemAvailable and already used swap; peak coexistence is not established. Do not shrink existing budgets or use this as deployment approval.
